Why bother

Design tokens usually get reconstructed by hand — zooming into screenshots, guessing hex, eyeballing padding, then typing the same decisions into every toolchain. Copy That’s contract is simpler: screenshot → reliable tokens → W3C + CSS (and React / Tailwind), with a light overview. Lighting, geometry, and mood board stay parked until that spine is solid.

Hard parts

CV + Claude extractors

Vision maps structure; the model names and organizes. Families live under src/copy_that/extractors/ with a capability map — not one opaque prompt.

Compat+ vs strict DTCG

Official $type coverage with intentional deltas (hex colors, spacing section naming, layout group), written down in W3C_CONFORMANCE.

Park vs delete

Mood board, lighting, geometry, sessions stay in-tree or mounted but off the default UI. Spine first.

Decisions that stuck

  • W3C Design Tokens as interchange New families plug into the same graph → export path.
  • Spine before platform P0–P3 center extract/export/overview; P4 parked; P5 only after the happy path holds.
  • Synth vs extract, named Some $types are derived or preset at export with confidence thresholds — documented, not oversold.
  • Illustrative apps ≠ product output Home shows why tokens matter; the ship is extract + export.
