From an image to a reusable style

How Copy That analyzes images, what is difficult to get right, and where to check the implementation. Technical terms are explained as they appear.

Why this helps

Matching a visual style by hand means comparing colors, identifying text styles, estimating distances, and recreating those choices in each tool. Copy That aims to make that repetitive work easier: find the details an image can support, organize them as reusable values, and share them with people and AI agents. This supports repeated experiments with an interface’s look. Extra tools, such as inspiration boards (Mood), lighting analysis, and layout measurements, run only when requested. The current implementation focuses on interface images; broader image sources need separate validation.

For developers: the application has a Python server (FastAPI), a browser interface (React 19 and TypeScript, built with Vite 8), and a Postgres database. Analysis combines AI assistance from Claude with color calculations (ColorAide) and computer vision—the automatic interpretation of images—using OpenCV. Optional tools can process Mood jobs in the background.

What is difficult to get right

Finding trustworthy visual details

Image-processing software measures visual details; Claude, an AI model, helps interpret and name them. Separate analyzers handle colors, text, spacing, and shadows. Developers can inspect these under src/copy_that/extractors/.

A shared file format

W3C, an organization that develops web standards, hosts the Design Tokens Community Group (DTCG). This group publishes a common file format for reusable style values. Copy That supports its defined categories and documents the differences in W3C_CONFORMANCE. Developer downloads include JSON (structured data), CSS (website styling), React themes (app styling), and Tailwind configuration (a website styling tool).

Keeping extra work optional

Inspiration boards and lighting analysis run only when requested. A hosted inspiration-board service requires sign-in. Uploads use the core image-analysis workflow; larger models for depth or layout measurements stay out of it. Session and bulk-processing services are configured separately.

Decisions behind the project

  • Style values that can move between tools Each analyzer feeds the same organized set of values and download formats. That gives people and software a consistent starting point.
  • Dependable results before broader features Improve how accurately the tool reads images before adding more board-generation features, input types, or collaboration tools.
  • Show where a value came from Some values are measured from the image; others are calculated or supplied as defaults. The project documents those differences rather than treating every value as directly observed.
  • Label concept studies clearly The home-page concepts show how a shared style could look across products. They are illustrations; the current application analyzes images and creates reusable downloads.

What comes next

Make color results more faithful to the source image, test against a wider set of labelled examples, and verify that saved and downloaded values remain consistent. The broader goal is faster, repeated design experiments with a language people and AI agents can both use. Hosted access has a separate invited-demo plan; this website is a project showcase.
